# opencode-experientiallabs

> **This repository was generated by AI (OpenCode + GLM).**

An [OpenCode](https://opencode.ai) V2 plugin that adds Experiential Labs as a model provider with a dynamic, per-account model catalog. Instead of a hardcoded model list, the plugin fetches the catalog from the Experiential gateway (`/v1/models`) at startup — every chat model your account can route (hosted, BYOK, and local GPU models) is registered automatically and enriched with metadata from Experiential's own model catalog API (`/api/models`).

## Requirements

- OpenCode V2 (built against `@opencode/plugin` 2.x)
- Node ≥ 22.6 — only needed to run the test suite; OpenCode bundles its own runtime

## Install

**From GitHub (canonical):**

```
opencode plugin add github:epicawesomesauce/opencode-experientiallabs
```

> Requires an OpenCode **v2** CLI — check with `opencode --version`. The v1 CLI (`opencode-ai` ≤ 1.18.x) has no `plugin add` subcommand and treats `add` as an npm package name, silently installing an unrelated package.

Refresh after new commits with `opencode plugin update`.

**Via config file** — add the spec string to the `plugins` array in `opencode.json(c)`:

```jsonc
{
  "plugins": ["github:epicawesomesauce/opencode-experientiallabs"]
}
```

> Some builds (e.g. desktop 2.0.24) read the V1 `plugin` singular key; both keys accept npm/git spec strings.

**Local development** — some builds silently drop local directory paths in the config plugin array (observed on desktop 2.0.24). The working mechanism is a shim file in the global plugin discovery dir, `~/.config/opencode/plugins/experiential.ts`, with one line pointing at this checkout:

```ts
export { default } from "file:///abs/path/to/opencode-experientiallabs/src/index.ts"
```

Newer builds may support config-array local paths directly.

## Configuration

The gateway base URL defaults to `https://api.experientiallabs.ai/v1`. Override it with the plugins-array object form (options are consumed as `ctx.options`), e.g. to point the provider at a local `exp` gateway:

```jsonc
{
  "plugins": [
    {
      "package": "github:epicawesomesauce/opencode-experientiallabs",
      "options": { "baseURL": "http://127.0.0.1:8000/v1" }
    }
  ]
}
```

## Authentication

Two flows; the connection wins when both are present:

1. **`/connect`** — run `/connect`, select **Experiential**, paste your `xpl_...` API key (the integration registers a key-paste method with an `apiKey` form field). The key is stored server-side as a credential and the provider is registered with `sourceConnection`.
2. **Environment fallback** — set `EXPLABS_API_KEY`, used when no connection exists. It must be visible to the OpenCode server process: desktop apps inherit user-scoped env vars; in CLI contexts export it in the launching shell.

## Behavior notes

- Dynamic catalog: every chat model the account can route (hosted + BYOK + local GPU; 300+ models). Drifts with the account — new upstream models appear with zero maintenance.
- Metadata: limits/pricing/tools/reasoning fields come from the gateway `/v1/models`; display names, vision capabilities, and release dates are enriched from Experiential's own catalog API (`{apiBase}/api/models`) via a slug-exact join on the model id. Unmatched models simply keep their id as the display name.
- Caching: catalog TTL 10 min, metadata TTL 24 h; instant provider registration from cache on boot; stale-serve on gateway outage (the provider stays listed, like a built-in with a bad key).
- Disconnect: removing the credential removes the connection-scoped provider until reconnect or service restart (same as built-ins); the env fallback re-registers on the next boot/reload.
- Known v1 limitations: after a full disconnect (no credential AND no env var) a previously-registered provider can linger in the catalog until restart; per-key cache entries are not evicted; refresh failures log on every catalog evaluation during an outage.

## Migrating from a static custom provider

If you previously configured Experiential as a static custom provider (e.g. id `explabs`):

1. Remove its `provider`/`providers` block from your OpenCode config.
2. Rename all model references `explabs/<model>` → `experiential/<model>` (agent `model` fields, `model`, `small_model`).
3. Connect via `/connect` or set `EXPLABS_API_KEY`.
